Chapter 9: Frequency × Severity — The Traditional Approach

You want to know how much money to save for car repairs this year.
Step 1: How many times will your car break down? (maybe 0.3 times/year on average)
Step 2: When it breaks, how much does the mechanic charge? (maybe $2,000)
Answer: Save 0.3 × $2,000 = $600/year. That's insurance pricing in a nutshell.

The Fundamental Equation of Insurance Pricing

Pure Premium = Frequency × Severity

E[Total Loss] = E[Number of Claims] × E[Cost per Claim]

In symbols: E[Y] = E[N] × E[S]

Why Do We Build Two Separate Models?

Why not just build one model directly on total claims?

Good question! There are actually good reasons for splitting:
1. Different drivers: What makes claims more FREQUENT (e.g., bad safety culture) may differ from what makes them more EXPENSIVE (e.g., expensive jurisdiction like US courts)
2. Different data: Frequency uses all 35,650 policies. Severity only uses the 3,610 with claims.
3. Better diagnostics: If the model is wrong, you can pinpoint whether frequency or severity is off.

BUT: there's a shortcut that combines both → Tweedie (Chapter 11).

How Each Model Works

Frequency Model (Poisson GLM)

# R code
glm(n_claims ~ log10(exposure) + country + trade,
    family = poisson(link = "log"),
    offset = log(duration),
    data = all_policies)

# Python equivalent
sm.GLM(y_freq, X, family=sm.families.Poisson(), offset=log_duration).fit()

Key details:

  • Response: number of claims (0, 1, 2, ...)
  • Uses ALL policies (including zeros)
  • Offset = log(duration) — a 2-year policy has ~2× the chance of a claim
  • Poisson distribution — natural for count data
  • Log link — ensures positive predictions, multiplicative effects

Severity Model (Gamma GLM)

# R code
glm(avg_claim_size ~ log10(exposure) + country + trade,
    family = Gamma(link = "log"),
    data = claims_only)  # ONLY policies where claims > 0

# Python equivalent
sm.GLM(y_sev, X, family=sm.families.Gamma(link=sm.families.links.Log())).fit()

Key details:

  • Response: average claim size (positive continuous)
  • Uses ONLY policies with claims > $0
  • NO offset (duration doesn't affect how big a claim is, only how likely)
  • Gamma distribution — positive, right-skewed
  • Log link — same benefits as frequency model

The Problems With Two Models

❌ Drawbacks

  • Double the work: build, validate, monitor TWO models
  • Independence assumption: assumes frequency and severity are independent (often violated)
  • Severity model only uses 10% of data (policies with claims)
  • Combining predictions requires manual multiplication

✅ Advantages

  • Better diagnostics — see what's driving each component
  • Different variables can affect frequency vs severity
  • More interpretable for actuarial communication
  • Traditional approach — familiar to regulators

Chapter 10: Maximum Likelihood Estimation (MLE)

You found a bag of marbles. Some are red, some are blue. You pull out 7 red and 3 blue. You want to guess what fraction of ALL marbles in the bag are red. MLE says: "Find the fraction that would have made your sample of 7 red and 3 blue the MOST LIKELY outcome." The answer is obviously 70%. That's MLE — find the parameter that makes your observed data most probable.

The Idea

Given observed data y₁, y₂, ..., yₙ and a model with parameters θ:

Likelihood: L(θ) = P(data | θ) = Π f(yᵢ | θ)

Log-likelihood: ℓ(θ) = Σ log f(yᵢ | θ)

MLE: θ̂ = argmax ℓ(θ) — the parameters that make the data most likely

MLE for the Poisson — Step by Step

Let's walk through MLE for Poisson with REAL numbers. You have 10 policies with these claim counts: [0, 0, 0, 0, 0, 0, 0, 1, 0, 2]. What's the best λ?
  1. Write the likelihood: L(λ) = Π P(yᵢ | λ) = Π [e−λ × λyᵢ / yᵢ!]
  2. Take the log: ℓ(λ) = Σ [−λ + yᵢ × log(λ) − log(yᵢ!)]
    = −nλ + (Σ yᵢ) × log(λ) − Σ log(yᵢ!)
  3. Take the derivative and set to 0:
    dℓ/dλ = −n + (Σ yᵢ) / λ = 0
  4. Solve: λ̂ = (Σ yᵢ) / n = the sample mean!

For our example: λ̂ = (0+0+0+0+0+0+0+1+0+2) / 10 = 0.3

For Poisson, MLE gives λ̂ = sample mean. That's comforting — the best estimate of the average rate is just the average! For more complex distributions (like Gamma or Tweedie), there's no simple closed-form solution, so we use numerical optimization (the computer finds it iteratively).

MLE for GLMs — The IRLS Algorithm

In a GLM, we don't estimate a single λ. We estimate coefficients β₀, β₁, β₂... that predict different λ's for different risks. MLE for GLMs uses an algorithm called IRLS (Iteratively Reweighted Least Squares):

  1. Start with a guess for coefficients β
  2. Compute predictions μ = g−1(Xβ) using the link function
  3. Compute weights based on the variance function (heavier weights for more reliable observations)
  4. Fit a weighted regression to get improved β
  5. Repeat until β stops changing (convergence)
Imagine you're adjusting a recipe. You make a batch, taste it, adjust the salt. Make another batch, taste, adjust. Keep going until it tastes perfect. That's IRLS — the computer adjusts the coefficients in rounds until the model fits as well as possible.

Log-Likelihood: How We Compare Models

The log-likelihood tells us how well a model fits the data. Higher = better fit. Two important derived metrics:

📊

AIC

AIC = −2ℓ + 2k

Penalizes for number of parameters (k).
Lower = better.

Use when: comparing non-nested models

📈

BIC

BIC = −2ℓ + k × log(n)

Stronger penalty for parameters than AIC.
Lower = better.

Use when: want a simpler model

AIC rule of thumb: If Model A has AIC 1000 lower than Model B, A is dramatically better. If the difference is < 2, they're essentially equivalent. Differences of 2–10 suggest moderate evidence.

Chapter 11: The Tweedie Distribution — The Insurance Distribution

Instead of separately asking "how many phone calls today?" (Poisson) and "how long is each call?" (Gamma), Tweedie asks one question: "How much total time did you spend on the phone today?"

Answer might be 0 minutes (no calls = most days), 15 minutes (one short call), or 90 minutes (a few long calls). ONE distribution handles it all.

The Mathematical Definition

If N ~ Poisson(λ) and each claim Sᵢ ~ Gamma(α, β), then:

Y = S₁ + S₂ + ... + SN ~ Tweedie(μ, φ, p)

This is called a Compound Poisson-Gamma distribution.

The Magic: Tweedie = Poisson × Gamma Automatically

Why p = 1.5 for your construction model:
  • ~90% zeros → strong Poisson component (pulls toward p=1)
  • Non-zero claims are heavily right-skewed → Gamma component (pulls toward p=2)
  • p = 1.5 is the balanced midpoint that actuaries have found works well for GL

How to Estimate p From Data

# R: Profile likelihood for p
library(tweedie)
out <- tweedie.profile(claims ~ log10(exposure) + country,
                        data = df,
                        p.vec = seq(1.1, 1.9, by=0.1))
# Picks the p that maximizes the likelihood

# Or just use p=1.5 as a good default for insurance
In practice, most insurers use p = 1.5 as a starting point for GL/construction. Some do a profile likelihood search (trying p = 1.1, 1.2, ..., 1.9 and picking the best). Your R code uses tw(p=1.5) directly.

Tweedie vs Freq × Sev — They Give the Same Answer!

Here's the beautiful part: Tweedie with p between 1 and 2 IS MATHEMATICALLY IDENTICAL to Freq × Sev (Poisson × Gamma). You're not losing anything by using Tweedie — you're just doing the same thing more efficiently in one step.

Freq × Sev (2 models)

  • Build & maintain 2 models
  • Cross-validate each separately
  • Multiply at the end
  • Assumes independence
  • Severity model uses only 10% of data

Tweedie (1 model) ✅

  • Single model for total loss
  • One cross-validation
  • Handles zeros automatically
  • No independence assumption needed
  • Uses ALL data (100%)
Industry standard: Most modern pricing teams use Tweedie as the default. Freq × Sev is still used for: (a) diagnostics, (b) communication to non-technical stakeholders, (c) regulatory requirements that mandate separate models.

Chapter 12: The Variance Function — Why It's the Most Important Concept

Imagine you're throwing darts at a target. A beginner's darts are spread all over (high variance). A pro's darts cluster tightly (low variance). Now imagine the target changes size — bigger target = darts spread out more. The relationship between target size (mean) and dart spread (variance) is the variance function. In insurance: bigger companies have more variable losses.

Var(Y) = φ × V(μ) — The Key Equation

In every GLM, the variance of the response depends on the mean through a variance function V(μ):

Var(Y) = φ × V(μ)

Where φ is the dispersion parameter and V(μ) depends on the distribution chosen.

Why this matters: Choosing the wrong variance function means your model gives wrong standard errors, wrong confidence intervals, and wrong p-values. It also affects predictions for large vs small companies. The variance function is MORE important than the exact distribution shape in many practical situations.

The Dispersion Parameter φ

If the variance function V(μ) tells you the shape of how variance grows with the mean, then φ is the volume knob. Higher φ = more spread, lower φ = tighter predictions. Think of it as overall "noisiness" of the data.

Chapter 13: Overdispersion — When Poisson Isn't Enough

Poisson says: "if the average is 3, the spread should also be 3." But what if the actual spread is 10? That's called overdispersion — your data is messier than Poisson expects. It's like expecting all students to score within 5 points of the average, but some score 0 and some score 100.

How to Detect Overdispersion

# In R, after fitting a Poisson GLM:
model <- glm(n_claims ~ exposure + country, family=poisson, data=df)

# Check: residual deviance / degrees of freedom
# If >> 1, you have overdispersion
summary(model)$deviance / summary(model)$df.residual
# Your data: this might be ~2.5 (overdispersed!)

# In Python:
print(f"Dispersion: {model.deviance / model.df_resid:.2f}")
# If > 1.5, suspect overdispersion

Why Overdispersion Happens in Insurance

Overdispersion occurs because the Poisson model assumes all policies with the same exposure have the same λ. But in reality, even among policies with $10M exposure:
  • Some have great safety programs → low actual λ
  • Some have terrible safety → high actual λ
  • This unobserved heterogeneity creates extra variability
The more risk factors your model includes, the less overdispersion you'll see (because you're explaining the variation).

Three Solutions for Overdispersion

SolutionWhat It DoesCodeWhen to Use
Quasi-Poisson Adds a dispersion parameter φ. Same coefficients as Poisson, but wider standard errors. family=quasipoisson Quick fix. Same point estimates, honest uncertainty.
Negative Binomial A proper distribution for overdispersed counts. Var = μ + μ²/θ. MASS::glm.nb() When overdispersion is severe. More flexible than quasi-Poisson.
Switch to Tweedie ⭐ Sidestep the problem entirely. Model total loss, not counts. family=tw(p=1.5) Industry standard. Avoids the whole freq/sev split.
In practice, overdispersion in the frequency model is one more reason to prefer the Tweedie approach: you avoid the issue entirely by modelling total losses instead of counts.

The Negative Binomial — A Quick Look

Negative Binomial: P(X=k) = C(k+r-1, k) × (1-p)r × pk

Mean = μ     Variance = μ + μ²/θ     (always > μ, so overdispersed by design)
Think of Negative Binomial as "Poisson with extra randomness." In the Poisson, λ is fixed. In the Negative Binomial, λ itself is random (it follows a Gamma distribution). This extra layer of randomness naturally creates overdispersion.
