Chapter 15: The Three Components of a GLM

Linear regression is like a vending machine: you put in features (coins), it adds them up, and spits out a prediction. A GLM is a fancier vending machine with three customizable parts: (1) what the output looks like (distribution), (2) how to connect the features to the output (link function), and (3) the actual recipe of features (linear predictor).

Component 1: The Random Component (Distribution)

What kind of data are you modelling? This determines which distribution to use.

3. Linear Predictor

The recipe

The combination of your variables

Chapter 16: Link Functions — The Heart of the GLM

The link function is like a translator. Your model's brain works in one language (the linear predictor η), but your data speaks another language (the mean μ). The link function translates between them.

Log link: μ = eη — translates "any number" into "always positive"
Identity link: μ = η — no translation (like linear regression)

The Three Key Link Functions

LinkFormulaInverseUsed ForKey Property
Identityg(μ) = μμ = ηNormal (linear regression)No transformation
Log ⭐g(μ) = log(μ)μ = eηPoisson, Gamma, TweedieAlways positive, multiplicative
Logitg(μ) = log(μ/(1-μ))μ = 1/(1+e−η)Binomial (yes/no outcomes)Output between 0 and 1

The Log Link — Why It's Perfect for Insurance

Model (on link scale): log(E[Claims]) = β₀ + β₁X₁ + β₂X₂ + ...

Prediction (real scale): E[Claims] = eβ₀ × eβ₁X₁ × eβ₂X₂ × ...

See the magic? On the log scale, effects ADD. On the real scale, they MULTIPLY.

The Canonical Link

Each distribution has a "default" link function (the canonical link). You CAN use different links, but the canonical link has nice mathematical properties:

DistributionCanonical LinkPractical Link in Insurance
NormalIdentityIdentity
PoissonLog ✅Log ✅ (same!)
GammaReciprocal (1/μ)Log (not canonical, but practical)

In insurance, we almost always use the log link, even when it's not the canonical link for that distribution. The reason: multiplicative relativities are what underwriters need, and the log link provides them directly.

Chapter 17: Coefficients & Relativities — Reading GLM Output

When the model says "β_UK = 0.26", it doesn't mean "add $0.26." It means "UK is e0.26 = 1.30 times the base." That 1.30 is the relativity. It's the single most important number for pricing — it goes directly into the rating table.

From Coefficients to Relativities

For a log-link GLM:

Coefficient β: The model's raw output. On the log scale.
Relativity = eβ: The multiplicative factor. On the real scale.

If β = 0 → Relativity = e⁰ = 1.00 (no effect — this is the base level)
If β > 0 → Relativity > 1 (more expensive than base)
If β < 0 → Relativity < 1 (cheaper than base)

The Base Level — Why One Category "Disappears"

If country has 5 levels (AU, UK, CA, Asia, Others), the model only shows 4 coefficients. Where's Australia?

Answer: Australia is the base level (reference category). Its coefficient is 0, which means its relativity is e⁰ = 1.00. All other countries are measured RELATIVE to Australia. This is called dummy coding or treatment coding.

Changing the Base Level

The choice of base level doesn't change the predictions — it only changes how you read the coefficients. But it matters for communication:

# R: Change base level to UK
df$country <- relevel(factor(df$country), ref = "United Kingdom")

# Now UK has coefficient 0, and Australia would have a NEGATIVE coefficient
# (meaning Australia is cheaper than UK)
Best practice: Choose the base level that makes business sense. In your case, Australia is the largest portfolio → natural base. All relativities then show "how much more/less than Australia."

Chapter 18: Offsets & Exposures in GLMs

An offset is like telling the model: "I KNOW this relationship is proportional. Don't waste time estimating it — just lock it in." The most common offset is policy duration: a 2-year policy should have exactly 2× the expected claims of a 1-year policy. Not 1.97×, not 2.03× — exactly 2×.

What Is an Offset?

Without offset: log(E[Y]) = β₀ + β₁X₁ + β_dur × log(Duration)
→ Model estimates β_dur ≈ 1 (wastes a degree of freedom)

With offset: log(E[Y]) = β₀ + β₁X₁ + 1 × log(Duration)
→ Coefficient FIXED at 1 (no estimation needed)

Which means: E[Y] = eβ₀ + β₁X₁ × Duration

Common Offsets in Insurance

OffsetWhyCode
log(Policy Duration)2-year policy = 2× riskoffset = log(PolicyDurationYear)
log(Earned Exposure)Bigger company = proportionally more riskoffset = log(TradeExposureUSD)
log(Number of Vehicles)Motor: more cars = more accidentsoffset = log(n_vehicles)
When NOT to use an offset: Only use an offset when the relationship is truly proportional. If doubling the exposure doesn't exactly double the expected claims (it might do more or less), then exposure should be a regular variable, not an offset. In your construction model, duration is an offset but exposure is a regular variable (with a spline).

Your Model's Offset in Detail

# R code
bam(claims ~ s(log10(exposure), k=5) + country + trade + binder,
    family = tw(p=1.5),
    offset = log(PolicyDurationYear))  # ← OFFSET

# This means:
# log(E[claims]) = β₀ + f(log10exp) + β_country + ... + log(Duration)
# E[claims] = [base × exposure_factor × country_factor × ...] × Duration
The offset separates the rate (claims per year) from the volume (how many years of exposure). This is fundamental — your model estimates the RATE, and the offset scales it by duration.

Chapter 19: Categorical Variables — Dummy Coding & Factor Levels

Your model can't understand words like "Australia" or "United Kingdom." It only understands numbers. So we convert each category into a set of 0/1 flags. "Is this policy from UK?" → 1 or 0. "Is it from Canada?" → 1 or 0. These flags are called dummy variables.

How Dummy Coding Works

For a variable with L levels, we create L-1 dummy variables. The missing level is the base:

PolicyCountryis_UKis_CAis_Asiais_Others
P001Australia0000
P002UK1000
P003Canada0100
P004Asia0010
P005Others0001
Australia has all zeros → it's the base. Its effect is absorbed into the intercept β₀. Every other country's coefficient measures "how different from Australia?"

Why L-1, Not L Dummies?

If you created a dummy for ALL 5 countries (including Australia), the columns would be perfectly correlated: is_AU + is_UK + is_CA + is_Asia + is_Others = 1 always. This is called multicollinearity and breaks the model. Dropping one level (the base) fixes this.

Handling Variables With Many Levels

NAICS codes might have 200+ levels. You can't give each one its own coefficient (not enough data). Solutions:

  1. Group similar levels: Combine all plumbing codes into "Plumbing." Your data groups 70 countries into 5 groups.
  2. Keep only significant levels: Test which levels are significantly different from the base. Merge insignificant ones into "Other."
  3. Credibility threshold: Only keep levels with ≥ N claims (e.g., N=20). Levels with fewer claims → "Other."
  4. Regularization: Use shrinkage (Ridge/Lasso) to pull small-sample coefficients toward zero.
In your construction model, you grouped:
• 70 countries → 5 groups (AU, UK, CA, Asia, Others)
• Multiple trades → 2 groups (Construction, Other)
• 8 sources → 3 binder categories (not_binder, totten, pen)
This was driven by volume: each group needs enough claims to estimate a stable coefficient.

Chapter 20: Feature Engineering for Insurance

Your raw data has "revenue = $10,000,000." But the model works better with "log₁₀(revenue) = 7." Transforming raw data into model-ready features is called feature engineering. It's often the difference between a bad model and a great one.

The Most Important Transformations

1. Log Transform for Exposure

Raw: Exposure ranges from $100K to $10B (100,000× range)
Log₁₀: log₁₀(Exposure) ranges from 5 to 10 (just 5 units)

This compresses the scale and makes the relationship closer to linear (on the log-log scale).
Think about earthquake intensity: magnitude 5 vs magnitude 7 doesn't sound like much, but it's 100× different in energy. Using the Richter scale (which is log₁₀) makes comparisons easier. Same with exposure.

3. Creating Interaction Terms

What if the UK is more expensive for small companies but not for large ones? That's an interaction between country and exposure. Without an interaction term, the model assumes country has the same effect regardless of company size. 
# R: Add interaction
bam(claims ~ s(log10exp, k=5) + country + s(log10exp, by=country, k=3)  # ← INTERACTION
    family = tw(p=1.5), offset = log(Duration))

# The "by=country" creates a DIFFERENT smooth for each country
When to add interactions: Only when you have enough data. Each interaction term needs its own parameters. With 5 countries × 5 knots = 25 extra parameters, you need substantially more claims. In your model with 3,600 claims, simple interactions are OK; complex ones risk overfitting.

Chapter 21: Deviance & Residuals — How Good Is Your GLM?

After cooking a meal, you taste it. After fitting a model, you check the residuals. Residuals are the "leftovers" — the difference between what actually happened and what the model predicted. If the leftovers look random, the model is good. If there's a pattern, something is wrong.

What Is Deviance?

Deviance = 2 × [log-likelihood(saturated model) − log-likelihood(your model)]

The saturated model is the "perfect" model that has one parameter per data point (fits perfectly).
Deviance measures how far your model is from perfection. Lower = better.
Think of a test where the maximum score is 100 (saturated model). Your model scores 85. The deviance is like the 15 points you missed. Lower deviance = closer to the perfect score.

Types of Residuals in GLMs

The 4 Key Residual Plots

1. Residuals vs Fitted

Plot residuals against predicted values

Want: Random scatter around 0, no pattern

Bad sign: Funnel shape, curve, clusters

2. Q-Q Plot

Compare residual quantiles to Normal quantiles

Want: Points on the diagonal line

Bad sign: S-curve (heavy tails), banana shape

3. Residuals vs Each Predictor

Plot residuals against each X variable

Want: Random scatter — no remaining pattern

Bad sign: Curve = missing non-linearity → need GAM

4. Cook's Distance

Identify influential observations

Want: All points with low Cook's D

Bad sign: One point with huge Cook's D → investigate

Chapter 22: Variable Selection — What Goes in the Model?

You have 255 columns in your data. You can't put all of them in the model (it would overfit and be uninterpretable). Choosing the right variables is like packing a suitcase — take what you need, leave the rest behind.

The Variable Selection Process

  1. Start with domain knowledge: What SHOULD affect pricing? Exposure, country, trade, duration — these are obvious. Include them.
  2. Check one-way plots: For each candidate variable, plot actual loss rate vs the variable. Is there a signal?
  3. Fit the model with each variable: Does adding it improve AIC? By how much?
  4. Check statistical significance: Is the coefficient's p-value < 0.05?
  5. Cross-validate: Does the variable improve out-of-sample performance?
  6. Business sense: Can you explain why this variable affects the price? (Important for regulatory and underwriter buy-in)

Your approach at QBE: You tested 20+ candidate formulas using 20-fold cross-validation. For each formula, you computed Gini, AIC, deviance, and RMSE on held-out data. You picked the formula with the best average CV metrics. This is the gold standard.

Decision Framework: Include or Exclude?

Rule of thumb for insurance pricing: A good pricing model has 5–15 variables. More than that and you're overfitting. Less than 5 and you're probably missing important risk factors. Your QBE model has 4 variables (exposure, country, trade, binder) — lean and focused.
