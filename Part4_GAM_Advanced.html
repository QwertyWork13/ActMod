Chapter 23: GAM — Why Straight Lines Aren't Enough

A GLM draws a straight line (on the log scale). But real life isn't always straight. The relationship between company size and claims might curve — small companies have very few claims, medium ones have many, and very large ones level off. A GAM is like replacing the ruler with a flexible snake ruler that can bend to follow the data.

GLM vs GAM — The Core Difference

GLM: log(E[Y]) = β₀ + β₁ × X → Straight line

GAM: log(E[Y]) = β₀ + f(X) → Smooth curve

That f(X) is a smooth function that the data determines. The model learns the shape.

Chapter 24: How Splines Work — Step by Step

Imagine 5 friends (the "basis functions") standing along a number line. Each friend holds a different bell-shaped bump at their position. The model decides how much weight to give each friend's bump. Add all the weighted bumps together → you get a smooth curve. More weight on friend #3 → bigger bump in the middle. Negative weight on friend #5 → a dip at the end.

Step 1: Create Basis Functions

A spline with k knots generates (approximately k) basis functions B₁(x), B₂(x), ..., B_k(x).
Each Bᵢ(x) is a smooth curve that's "active" in a local region of x.

Step 2: The Model Learns Weights

f(x) = γ₁B₁(x) + γ₂B₂(x) + γ₃B₃(x) + γ₄B₄(x) + γ₅B₅(x) + γ₆B₆(x) + γ₇B₇(x)

The model estimates the weights γ₁, γ₂, ..., γ₇ using maximum likelihood.

Step 3: Add Weighted Basis Functions → Smooth Curve

The complete GAM is:
log(E[Claims]) = β₀ + γ₁B₁(x) + γ₂B₂(x) + ... + γ₇B₇(x) + β_UK × is_UK + ... + offset

The smooth part handles the continuous variable (exposure). The regular β coefficients handle the categorical variables (country, trade, binder). It's GLM + smooth = GAM.

Chapter 25: Smoothing Parameters & Penalization

Without any control, the spline could wiggle so much it passes through every data point — like connecting the dots with a crazy scribble. That's overfitting. The smoothing parameter λ acts like a "calm down" knob: higher λ = smoother (less wiggly) curve, lower λ = more flexible (more wiggly).

The Penalized Likelihood

GAM maximizes: Log-likelihood − λ × ∫ [f''(x)]² dx

• First part: fit the data well (high log-likelihood)
• Second part: penalty for "wiggliness" (integrated squared second derivative)
• λ balances the two: big λ → smooth, small λ → flexible

Think of k as the number of crayons you're allowed to have. λ is how carefully you color. With k=5 crayons, you can draw a moderately detailed picture. With k=20, you could draw very fine detail — but λ will stop you from over-coloring.

Effective Degrees of Freedom (EDF)

EDF tells you how many "effective parameters" the smooth uses:
• EDF = 1 → the smooth is essentially a straight line (GLM equivalent)
• EDF = 2 → gentle curve
• EDF = 3.5 → moderate curve (YOUR model)
• EDF = k-1 → maximum wiggliness allowed

If EDF ≈ 1, you don't need a GAM — a GLM would suffice.

Chapter 26: One-Way Analysis & Partial Dependence Plots

A one-way plot is like a science experiment: change ONE thing (like exposure), keep everything else the same (country, trade, etc.), and see what happens to the prediction. It shows the model's "opinion" on how each variable affects the price.

What Is a One-Way Plot?

For each variable, plot the model's predicted value as that variable changes, holding all other variables at their average/reference values.

How to Create One-Way Plots

# R: Plot smooth terms from GAM
plot(gam_model, pages=1, shade=TRUE, shade.col="lightblue")

# Or for full one-way plots:
library(mgcv)
vis.gam(gam_model, view="log10TradeExposureUSD_Inflated",
        type="response", plot.type="persp")

Chapter 27: Cross-Validation — The Honest Test

Cross-validation is like a student who studies from Chapter 1-19 of the textbook and then takes a test on Chapter 20. If they do well, they truly learned the material (not just memorized). We train the model on most of the data and test it on the held-out portion. Repeat multiple times for reliability.

K-Fold Cross-Validation — Step by Step

Your 20-Fold CV Process

# Pseudocode (what your cross_validate_model() does):
for formula in [formula1, formula2, ..., formula20]:
    for fold in 1:20:
        train = data[-fold]  # 19/20 of data
        test  = data[fold]   # 1/20 held out
        
        model = bam(formula, data=train, family=tw(1.5))
        predictions = predict(model, newdata=test)
        
        gini[fold]     = compute_gini(test$actual, predictions)
        deviance[fold] = compute_deviance(test$actual, predictions)
        rmse[fold]     = sqrt(mean((test$actual - predictions)^2))
    
    avg_gini[formula] = mean(gini)
    avg_rmse[formula] = mean(rmse)

best_formula = formula with highest avg_gini and lowest avg_rmse

Chapter 28: Lorenz Curves & The Gini Coefficient

Imagine sorting all your policies from "model thinks this is safest" to "model thinks this is riskiest." Then check: do the "risky" policies actually have more claims? The Lorenz curve shows this visually. If the model is perfect, 10% of the riskiest policies would account for way more than 10% of total claims.

How to Build a Lorenz Curve

  1. Sort all policies by the model's predicted risk (lowest → highest)
  2. Compute cumulative % of policies (x-axis)
  3. Compute cumulative % of actual claims (y-axis)
  4. Plot it — compare to the 45° "random model" line
Gini Coefficient = 2 × (Area between your model's curve and the 45° line)

Gini = 0 → Model is random (useless)
Gini = 0.3 → Decent discrimination (typical for insurance)
Gini = 0.5 → Very good
Gini = 1.0 → Perfect (impossible in practice)
A Gini improvement of 0.02–0.05 is meaningful in insurance pricing. If your GAM has Gini = 0.37 vs GLM's 0.35, that's a real improvement worth deploying.

Chapter 29: Lift Charts & Decile Analysis

Divide your policies into 10 equal groups (deciles) from lowest predicted risk to highest. Then check: does the actual loss rate increase across deciles? If decile 10 (highest predicted risk) has 5× the actual losses of decile 1 (lowest predicted risk), the model has good "lift."

How to Read a Lift Chart

A good model shows a clear "staircase" pattern: actual losses increase monotonically from decile 1 to decile 10. If decile 5 has higher actual losses than decile 7, the model's ordering is wrong in that region — investigate.

A/E (Actual vs Expected) Analysis

A/E Ratio = Actual Claims ÷ Expected (Predicted) Claims

A/E = 1.00 → Perfect calibration
A/E = 1.15 → Model underprices by 15% → needs adjustment
A/E = 0.85 → Model overprices by 15% → may lose business

Calculate A/E by key segments (country, trade, year) to check if the model is calibrated everywhere:

Chapter 30: Regularization — Ridge, Lasso & Elastic Net

When your model has many variables, some coefficients might be too large (overfit to noise). Regularization adds a "penalty" for large coefficients — like a teacher telling students "you can only write 500 words, not 5,000." This forces the model to focus on what really matters.

The Three Types of Regularization

Ridge (L2)

Penalty: λ × Σ β²

Shrinks ALL coefficients toward zero, but never exactly zero

Use when: Many correlated variables, want to keep all

Lasso (L1)

Penalty: λ × Σ |β|

Shrinks some coefficients to EXACTLY zero (automatic variable selection!)

Use when: Suspect many variables are irrelevant

Elastic Net

Penalty: α × Lasso + (1-α) × Ridge

Best of both worlds

Use when: Many variables, some correlated, want selection + stability

Penalized Log-Likelihood:

Ridge: ℓ(β) − λ × Σ βⱼ²
Lasso: ℓ(β) − λ × Σ |βⱼ|
Elastic Net: ℓ(β) − λ × [α × Σ |βⱼ| + (1-α) × Σ βⱼ²] 
# R: Regularized GLM with glmnet
library(glmnet)
fit <- glmnet(X, y, family=tweedie(var.power=1.5, link.power=0),
              alpha=0.5)  # Elastic net (alpha=0 → ridge, alpha=1 → lasso)

# Choose lambda by CV
cv_fit <- cv.glmnet(X, y, family=tweedie(var.power=1.5, link.power=0),
                     alpha=0.5, nfolds=20)
best_lambda <- cv_fit$lambda.min
In insurance pricing, regularization is useful when:
• You have many NAICS codes or ZIP codes as variables
• You want to automatically shrink unreliable coefficients (sparse data levels)
• You're building a GBM or ML model that needs regularization to prevent overfitting

For your GAM with 4 variables, regularization isn't critical — the model is already parsimonious. But it becomes essential for more complex models.

Chapter 31: Machine Learning for Pricing — GBMs & Random Forests

GLM/GAM are like a recipe you write yourself — you choose the ingredients and the cooking method. Machine Learning (ML) models like GBMs are like a robot chef that figures out its own recipe from the data. The robot might cook better, but it's harder to explain what it did to the health inspector (regulator).

Gradient Boosted Machines (GBM)

A GBM builds hundreds of simple decision trees, each one correcting the errors of the previous ones:

1. Fit a simple tree → Get residuals
2. Fit a second tree to the RESIDUALS → Add it to the model
3. Fit a third tree to the NEW residuals → Add it
4. ... repeat 500–2000 times

Each tree is weak (shallow). But combined, they're powerful.

Industry trend: Most insurers use GLM/GAM as the primary model (for rating tables and regulatory filings) and GBM as a benchmark to check if the GLM/GAM is missing something. If the GBM performs significantly better, the actuary investigates what interactions or non-linearities the GLM is missing.

When ML Models Beat GLM/GAM

  • Many variables: 50+ potential predictors → ML handles variable selection automatically
  • Complex interactions: "This NAICS code is risky in the US but not in Australia" → trees find this
  • Non-standard data: Text, images, telematics → ML can process these

When GLM/GAM Beats ML

  • Small data: 3,600 claims → ML overfits, GLM/GAM is stable
  • Regulatory requirements: Need to explain every factor to the regulator
  • Rating tables: Underwriters need simple multiplicative factors
  • Business buy-in: "The UK relativity is 1.30" is clearer than "the SHAP value is 0.26"

Chapter 32: BAM vs GAM — Scaling for Big Data

GAM is like a master chef cooking one plate at a time. BAM (Big Additive Model) is like an assembly line — same recipe, but optimized for cooking 10,000 plates efficiently. The food tastes the same; the kitchen just works faster.

Why BAM Exists

Standard GAM (via gam() in mgcv) computes a full smoothing matrix, which scales as O(n²). For n > 10,000 rows, this gets slow. BAM fixes this with:

OptimizationWhat It DoesImpact
Covariate discretizationRounds predictor values to reduce unique combinationsMassive memory savings
Parallel processingSplits computation across CPU cores2-4× speed on multi-core
Faster REMLUses a performance iteration instead of nested optimizationFaster convergence
# R: Your code uses BAM
library(mgcv)

# GAM (slower for big data)
model_gam <- gam(claims ~ s(log10exp, k=5) + country,
                  family = tw(p=1.5), data = df)

# BAM (same model, faster) ⭐
model_bam <- bam(claims ~ s(log10exp, k=5) + country,
                  family = tw(p=1.5), data = df)

# Results are statistically equivalent
For your 35K-row dataset, BAM runs noticeably faster than GAM. The coefficients, smooth curves, and predictions are essentially identical. Always use BAM when n > 10,000.
